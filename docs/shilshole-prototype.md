# Shilshole inspection prototype

This is the first executable slice of the project. It is an inspection tool, not a navigation chart or an S-52 implementation.

## Run locally

Requirements: Node.js 22.12+ (or a supported newer LTS), Python 3.10+, GDAL with the S-57 driver, and Felt tippecanoe with native PMTiles support and tippecanoe-decode. The initial build used GDAL 3.13.3 and tippecanoe 2.79.0. JavaScript dependencies are locked in package-lock.json; system binaries are not yet container-pinned.

```bash
brew install gdal tippecanoe
npm ci
npm run charts
npm run build
npm run preview
```

Open the localhost URL printed by Vite. Acquisition and installation need internet access; the built viewer does not. Keep the local server running when disconnecting the internet. Opening index.html directly through file:// is unsupported. For development use `npm run dev`.

Click the map to inspect original attributes and source cell identifiers. Sounding numbers appear from zoom 14 using their `depth_m` values; attributes remain available in the inspector. Hazard areas and lines have outlines. Toggle layers to inspect overlapping features. Grey background means no painted depth/land layer, not verified open water.

## Scope and provenance

`pipeline/shilshole.json` defines the test rectangle: west -122.43, south 47.66, east -122.38, north 47.70. It explicitly selects four active 1:12,000 cells from NOAA's catalog: US5SEAGK, US5SEAGL, US5SEAHK, US5SEAHL. Catalog bounding boxes nominated the cells; actual clipping currently extracts features from two of them. This is not proof of complete nautical coverage.

Each build downloads the current catalog and complete cell ZIPs from NOAA, retains the inputs under an ignored `build/` directory, and applies S-57 updates through GDAL. Catalog activation and scale changes fail the build for review. The manifest records editions, updates, source dates, ZIP hashes, tool versions, feature counts and archive hash. It records build time separately from source issue dates. A live catalog is not a reproducible snapshot; retained inputs are needed to investigate a particular build.

The chosen object classes are a subset of the ENC. Features outside the rectangle are clipped. Overlapping cells, coverage gaps, datum interpretation, SCAMIN, geometry quantization and presentation all require additional review. Do not interpret an absent layer or zero count as proof that there are no hazards.

## Validation

```bash
npm test
npx playwright install chromium
npm run test:browser
```

The pipeline disables density dropping, tile feature/size caps, line simplification and tiny polygon reduction. It decodes the resulting archive at maximum zoom and fails if an extracted feature identity is missing or a sounding depth changes. Individual soundings include coordinates in their key because split soundings can share the same S-57 LNAM. Features crossing tile boundaries are counted once by identity.

This check tests retention from extracted GeoJSON to maximum-zoom MVT. It does not prove faithful extraction from S-57, complete geometry retention, accuracy at every zoom, or correct nautical portrayal. Source attributes are available for manual review. GDAL can emit a SOUNDG dimensionality warning during clipping; the build independently requires every exported sounding to have a 3D coordinate and compares its copied depth with the decoded tile attribute.

The browser test blocks external requests, requires a real feature to be inspectable, checks for HTTP 206 archive responses and page errors, and exercises a layer toggle. The MapLibre worker is bundled locally, along with JavaScript and CSS. No external basemap, font, or sprite service is used.

Initial measured result after adding per-sounding identifiers: 472,065 archive bytes; 922 extracted features including 479 soundings, 5 wreck features and 39 rock features. Build time was about six seconds on the development machine. These numbers describe this small rectangle and source snapshot, not Puget Sound.

## Outputs and next gate

- `build/shilshole-*/`: source ZIPs, catalog snapshot, clipped GeoJSON, compiler log and manifest.
- `web/public/charts/`: immutable archive filenames and the latest manifest. Previous archives remain available; no automatic cleanup.
- `dist/`: the complete locally served viewer, generated by `npm run build`.

The archive is copied before the manifest is replaced. Failed builds leave the previous manifest intact. Do not run builds concurrently. Rebuild the viewer after rebuilding charts. Old archives are currently also copied into dist; remove obsolete generated archives deliberately when packaging a bundle.

## Zoom-aware inspection style

The overview shows land and depth areas. Contours and aids appear at zoom 11, hazards and coverage boundaries at zoom 12, and sounding numbers at zoom 14. The layer list displays these thresholds. These are prototype display choices, not S-52 or SCAMIN rules. Collision handling can hide overlapping labels and symbols; a clear-looking view does not establish absence of hazards.

Symbols distinguish buoys (diamond), beacons (triangle), lights (star), wrecks (cross), rocks (plus) and obstructions (square). They do not encode the full source attributes, lateral color, light characteristics or danger classification. Sounding values are displayed in metres without converting datum or rounding to a nautical presentation convention. Images are rasterized from the local system font at runtime, so no remote fonts or sprites are needed. Font appearance may vary by operating system.

The URL hash retains zoom and position for revisiting inspection locations. Coverage review and comparison with a later NOAA edition remain separate work.
